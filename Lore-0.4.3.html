Changed

  • Mac navigation stays within reach when the sidebar is closed. The sidebar, Back, Forward, and New Note controls now remain pinned beside the window buttons instead of disappearing. Each has a quiet hover state and a shortcut tooltip, and the wider sidebar keeps the controls clear of the writing area.
  • Daily notes now wait until you open them. Lore resumes your last selected note after launch or a new day instead of silently creating today's note in the background. Opening Daily—from the sidebar, All Notes, or its keyboard shortcut—still creates it immediately, as does saving a shared capture.

Fixed

  • Notes open ready to read on iPhone and iPad. Selecting a note from the sidebar now starts at the top without summoning the keyboard or placing the caret at the end, and note titles sit closer to the top of the page.
  • Daily notes no longer duplicate on iPad. Opening the app each day could show two copies of that day's note (and the days before) with identical content, even though only one file existed on disk. The duplicates were phantoms from how the vault's location was spelled internally; existing ones clean themselves up on the next launch. (iPad)
  • Leaving Lore open no longer grows its memory over time. An idle window could quietly keep itself busy — retrying attachment previews that couldn't load, re-requesting the same iCloud downloads, and animating the Nearby Notes glow in the background — until after days the app's memory ballooned and macOS warned about low disk space. Preview loading now backs off and stays within a fixed memory budget, iCloud sync checks stop re-asking for files already on their way, and the glow pauses while the window is inactive. (Mac and iPad)

Added

  • Turn off the floating formatting bar. Settings → General → Editing hides the bar that appears over a selection, for a quieter page. Keyboard shortcuts keep working either way. (Mac)

Changed

  • Note previews show what a note is filed under. Hovering a [[link]] used to repeat the note's title along the bottom of the preview card. That row now lists the note's tags instead, with a count when there are more than fit. Notes without tags show when they were last edited. (Mac and iPad)
  • Opening on iPhone or iPad after writing on your Mac is much faster. Lore used to wait on iCloud before it could show you anything, so a few new notes on the Mac could leave the phone sitting on "Opening your notes…" for several seconds. It now puts your notes on screen straight away and picks up the other device's changes in the background. Starting the day's daily note no longer holds up the launch either.
  • Editing stays smooth in long notes. Typing now restyles just the paragraph you're working in rather than the whole document, and the note's structure is reused between keystrokes instead of rebuilt.
  • Less happens in the background while you write. The context panel, All Notes previews, and the ⌘K palette no longer redo their work on every keystroke and every save, and finding Nearby Notes is substantially quicker.
  • Large vaults open faster. Notes load in parallel and in bigger batches, and Lore skips the ones whose files haven't changed since it last read them.

Fixed

  • Renaming a note can no longer overwrite another note. If a note's new title collided with a file Lore couldn't see — most often one iCloud hadn't downloaded yet — the next autosave could silently replace that file's contents. Lore now checks the disk itself before renaming and safely backs out if the move fails.
  • Titles that start with a dot no longer make a note vanish. A title like ".journal" created a hidden file that disappeared from Lore on the next launch; leading dots are now dropped from the filename.
  • Frontmatter written by other apps survives. Dates in other tools' formats (like created: 2026-06-09) were silently deleted on first save, quoted values grew stray backslashes with every save, and nested metadata under keys Lore doesn't use was flattened or lost. All of it now round-trips untouched.
  • A lone #, -, >, or checkbox no longer styles the line below it. Typing just a heading, list, quote, or task marker briefly formatted the next line as if it belonged to the marker.
  • Code blocks keep their contents literal. Links, tables, images, [[wiki links]], and formatting markers inside `` fences were being styled and partially hidden; they now render as plain code, and formatting markers inside inline code` stay visible too.
  • Renaming a note no longer edits your code samples. A [[link]] inside a code block or inline code is treated as sample text: a rename leaves it alone, and it no longer counts as a backlink or as an existing link.
  • Bolding across already-bold text no longer scrambles the markers. A selection that touches part of a bold, struck, or highlighted run now merges everything into one clean span instead of leaving stray ** in the text.
  • Japanese and Chinese input no longer floods undo. Every keystroke of an in-progress composition was recorded as its own undo step and could save half-composed text; the finished word is now one step.
  • Attachment previews update when the file changes. An image or PDF edited outside Lore — or updated through iCloud — kept showing its old preview until relaunch.
  • Undo on iPad and iPhone is trustworthy again. Shake-to-undo and the three-finger gestures now share the same history as ⌘Z instead of quietly breaking it, and undoing a formatting command puts the cursor back where it was. Going back to a note also returns you to where you left off instead of the top.
  • A change on another device no longer makes Lore re-read everything. In some setups Lore couldn't tell which files had actually changed and re-read the whole vault on launch — the main reason opening on iPhone could stall. It now reads only the notes that really changed.
  • Your daily note is recorded as soon as it's created, so opening Lore again later the same day doesn't go looking for it on iCloud.
  • Formatting a heading no longer breaks it. Selecting a whole heading line — by dragging across it or with ⌘A — and applying bold, italic, or highlight now wraps the heading's text instead of swallowing the # and destroying the block.
  • Toggling formatting off actually removes it. Un-bolding or un-striking text whose selection caught the surrounding markers no longer doubles them up, including where styles are nested.
  • Text no longer jumps as you start typing a heading. The caret is now the right size and in the right place on a heading whose markers have just been hidden, and the first character you type lays out at its final size.
  • Dragging a panel edge works on the first try. The sidebar and context-panel edge grips no longer lose the click to the text behind them.
  • The context panel opens fully drawn. Revealing it with ⌘⌥I no longer pops its sections in one after another.
